# boumax-cloud-routine

Bron-repo voor de dagelijkse Boumax-acquisitie cloud-routine "Boumax - dagelijkse pipeline (mail + opvolging + demo)" (08:00 Europe/Amsterdam / 06:00 UTC). Voert drie stappen uit in één sessie: mailstatus checken, opvolging checken (Slack), en pas daarna een nieuwe demo bouwen — zie hieronder.

**Bevat:**
- `deploy/` — exacte huidige staat van de live site boumax.nl (index.html, privacy.html, branding, en per-prospect demo-mappen zoals `demo-sikkens/`). Dit is precies wat elke keer als geheel naar Netlify gaat — nooit alleen de nieuwe demo apart deployen, anders verdwijnt de rest van de live site.
- `website-demo-schilders/` — het generieke, nog niet gepersonaliseerde demo-sjabloon (demo.html + images/) waar een nieuwe prospect-demo op gebaseerd wordt.
- `netlify-deploy/deploy.py` — deployt de hele `deploy/`-map naar boumax.nl via Netlify's API (token via lokale `.env`, nooit gecommit). **Heeft twee modi:**
  - Zonder argumenten: uitgebreide lokale sync met Git (fetch + echte driewegsmerge + push), voor gebruik op de ontwikkelmachine. Importeert `sync_with_github.py`, dat bewust NIET in deze repo staat.
  - **`--cloud`**: slaat die sync over en deployt gewoon de `deploy/`-map zoals die in deze kloon staat. **De dagelijkse cloud-routine gebruikt altijd `--cloud`** — zonder die vlag crasht het script met `ModuleNotFoundError` omdat `sync_with_github.py` hier ontbreekt (dat is opzettelijk: de cloud-sandbox kan toch niet naar deze repo pushen, dus die module heeft daar geen functie).
- `hostinger-drafts/draft_tool.py` — slaat een kant-en-klare mailtekst uitsluitend als concept (IMAP `\Draft`) op in de Hostinger-mailbox. Bevat geen SMTP-code, kan fysiek geen e-mail versturen. **Alleen voor lokaal gebruik door Johan** — de cloud-routine gebruikt dit script sinds 20-08-2026 niet meer: de Claude-cloud-sandbox blokkeert uitgaand verkeer op poort 993 (IMAP) structureel, dus dit kan vanuit de routine nooit slagen. De routine schrijft de kant-en-klare mailtekst in plaats daarvan naar de Notitie-kolom van de prospect-sheet; Johan zet 'm zelf lokaal in een concept met dit script, of verstuurt 'm rechtstreeks.
- `.github/workflows/sync-demos.yml` + `scripts/sync_missing_demos.py` — een aparte, dagelijkse GitHub Action (draait op GitHub's eigen infra, niet in de Claude-sandbox, cron `0 8 * * *` = 10:00 Europe/Amsterdam in de zomer / 09:00 in de winter) die automatisch demo-mappen die live staan op Netlify maar nog niet in deze repo staan, terugzet. Dit is de manier waarop nieuwe demo's van de cloud-routine in deze repo terechtkomen — de routine zelf probeert nooit te pushen (dat lukt structureel niet vanuit de Claude-cloud-sandbox, bevestigde bug in Anthropics GitHub-connector). De Action draait bewust 2 uur ná de dagelijkse pipeline-start (06:00 UTC), zodat de pipeline's eigen deploy niet per ongeluk een net teruggezette demo-map weer overschrijft. Als extra vangnet doet de pipeline ook zelf `git fetch origin && git reset --hard origin/main` vlak vóór het bouwen van een nieuwe demo (zie hieronder) — de tijdsbuffer is dus niet de enige bescherming tegen deze drift. (Dit was aanvankelijk `git pull --ff-only`, maar dat faalt structureel in de cloud-sandbox omdat die de repo altijd in een detached-HEAD-state klont; gevonden en gefixed tijdens de eerste testrun op 20-08-2026. Veilig omdat deze kloon een wegwerpkopie is die nooit zelf commit of pusht.)

**Nooit in deze repo:** wachtwoorden, Hostinger-mailwachtwoord, of enig `.env`-bestand. Het Netlify-token en het sheet-webhook-token worden per routine-run apart meegegeven, niet hier opgeslagen.

**Workflow van de dagelijkse routine:** zie de routine-configuratie zelf (via claude.ai/code/routines) voor de volledige instructies. Kort samengevat, in vaste volgorde binnen één sessie: (1) mailstatus checken (Hostinger-mailbox vs. sheet, statussen bijwerken), (2) opvolging checken (verlopen opvolgdatums → Slack-DM naar Johan), (3) `git fetch origin && git reset --hard origin/main` op deze kloon, dan pas kies volgende prospect uit de sheet → personaliseer een nieuwe map onder `deploy/demo-<naam>/` → `python netlify-deploy/deploy.py --cloud` → verifieer live → schrijf de mailtekst naar de Notitie-kolom. Nieuwe demo-mappen komen automatisch in deze repo terecht via de aparte GitHub Action hierboven, niet doordat de routine zelf commit/pusht.
